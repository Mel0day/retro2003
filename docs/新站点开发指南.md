# 怎么再复刻一个站点

这个项目的每个站点都是一个独立的 Node.js 应用，放在 `sites/<名字>/` 下。加一个新站不需要改动已有站点，照下面的顺序走即可。

## 一、先想清楚「它在 2003 年会是什么样」

在写代码之前，先回答三个问题：

1. **当年有没有对应的东西？** 微信对应 OICQ/MSN，Notion 对应企业内网和 BBS，Spotify 对应音乐盒和电台。找到那个年代的真实对应物，界面就有了参照。
2. **哪些功能当年做得出来？** 2003 年没有 WebSocket（用轮询或 iframe 长连接的效果，本项目用 SSE 模拟）、没有扫码支付、没有推荐算法信息流、没有无限滚动。做不出来的功能要么砍掉，要么换成当年的替代物（比如即时聊天换成留言板）。
3. **核心体验是什么？** 复刻的价值在于把核心闭环做通：小红书是「发内容 → 被看到 → 有人回应」，淘宝是「找到宝贝 → 付款 → 发货 → 确认 → 评价」。外围功能可以少，核心闭环必须完整。

把结论写成 `sites/<名字>/docs/需求拆解.md`，再开始写代码。

## 二、目录骨架

直接照抄 `sites/taobao2003` 的结构最省事：

```
sites/<名字>/
├── package.json          # 依赖：express、nunjucks、better-sqlite3、（需要上传就加 multer）
├── Dockerfile            # 照抄，改端口和 COPY 的目录
├── docker-compose.yml    # 单站部署用
├── .env.example
├── src/
│   ├── config.js         # 读环境变量，确定数据目录、密钥、端口
│   ├── app.js            # 组装中间件、模板过滤器、路由、错误页
│   ├── server.js         # 启动与优雅退出
│   ├── db/{index.js,schema.sql}
│   ├── lib/              # 格式化、文本清洗、限速、分页、密码、上传
│   ├── middleware/       # cookie、安全响应头、访客 ID、CSRF
│   ├── services/         # 业务逻辑（登录会话、交易、信用……）
│   └── routes/           # 每个领域一个文件
├── views/                # Nunjucks 模板，layout + 各页面
├── public/{css,js,img,fonts}
├── scripts/              # seed-data.js、seed.js、backup.js、crawl.mjs
├── seed/images/          # 演示配图与 credits.json
├── test/                 # 集成测试 + test/e2e 浏览器测试
└── README.md             # 功能清单、路由表、数据模型、演示账号、已知限制
```

点阵字体直接从已有站点复制 `public/fonts/` 和 `public/css/fonts.css`（两个站的字体文件是同一份）。

## 三、必须遵守的约定

**视觉**

- 页面宽度用当年的固定像素（778px 或 800px），表格排版，不用 flex 大留白和圆角卡片。
- 凡是写 `font-size` 的地方都要同时写对应的点阵字体族变量：`font-size:12px;font-family:var(--f-song-12)`。字号和字族不匹配，点阵字会被缩放糊掉。
- 允许的年代元素：渐变标题条、跑马灯、闪烁 NEW、访客计数器、IE 推荐分辨率角标、友情链接、站长公告。

**功能**

- 服务端渲染 + 表单提交为主，JavaScript 只做渐进增强；关掉 JS 站点也能用。
- 数据落 SQLite，金额一律用「分」保存的整数。
- 演示数据要撑得起门面：几十个会员、上百条内容、按时间散布，第一屏就有密度，并且 `seed` 必须幂等。

**安全**（这几条每个站都要做到，测试里也要覆盖）

- 所有 POST 带 CSRF 令牌（只认表单字段或请求头，不认 URL 参数）。
- 模板默认转义；SQL 全部参数化；`LIKE` 做转义。
- 越权校验：别人的订单、地址、内容一律 404 或 403。
- 登录、注册、发帖、下单都有按 IP 或按会员的限速。
- 响应头：CSP（`script-src 'self'`）、nosniff、X-Frame-Options、Referrer-Policy。
- 上传按文件头识别图片类型，不信任扩展名，不接受 SVG。

**测试**

- 集成测试覆盖每个功能点的主路径和关键错误路径（未登录、越权、非法输入）。
- 至少一个浏览器端到端测试走完核心闭环，并断言控制台零报错。
- `scripts/crawl.mjs` 爬一遍站内链接，确认没有 404/500 和模板残留。

## 四、接进仓库

1. 在根目录 `docker-compose.yml` 里加一个服务，端口顺延（3005、3006……）。
2. 在根目录 `package.json` 的 `setup` / `dev:*` / `test` 脚本里加上新站点。
3. 在根目录 `README.md` 的站点清单表里加一行，并放两张截图到 `docs/screenshots/`。
4. 跑一遍 `npm test` 和 `npm run test:e2e`，确认两个老站点没有被影响。
