# 怎么把一个现代产品拆成 2003 年的样子

## 一、先定核心闭环

问自己：用户来这个站，最重要的一件事是什么？把它写成 3-6 步，每一步都必须在站点里真的走通。

- 小红书：注册 → 发笔记（带图）→ 被人看到（列表/排行）→ 有人留言/顶 → 作者回复
- 淘宝：找到宝贝 → 下单付款（担保）→ 卖家发货 → 确认收货 → 双方评价
- 音乐站：找到歌 → 试听 → 收藏进歌单 → 分享歌单给别人

闭环之外的功能都是可选的。先把闭环做完，再加外围。

## 二、角色

至少三种，权限要真的隔离：

| 角色 | 典型能力 | 必须验证 |
| --- | --- | --- |
| 游客 | 浏览、搜索、（可选）加购物车 | 写操作一律跳登录 |
| 会员 | 发布、互动、管理自己的东西 | 只能改自己的，别人的返回 404/403 |
| 站长 | 统计、封禁、隐藏内容、站点设置 | 普通会员访问后台返回 403 |

## 三、砍掉与替代

逐条列出现代产品的主要功能，标注「保留 / 换成 XX / 砍掉」，并写理由。理由要么是「当年技术做不到」，要么是「当年的产品形态就不是这样」。这张表直接写进 `docs/需求拆解.md`，也是 README 里「与现代版的差异」那一节。

## 四、页面清单

一个 2003 年的站通常是这些页面，按需要裁剪：

1. 首页（列表 + 左栏导航 + 右栏排行/公告）
2. 详情页（内容 + 互动 + 盖楼留言）
3. 发布/编辑页
4. 列表页的筛选与搜索结果
5. 登录、注册
6. 个人中心（我的东西、资料、改密）
7. 他人主页/店铺
8. 说明页（关于、帮助、联系、规则）
9. 站长后台（统计、会员、内容、设置）
10. 提示页（操作成功/失败，3 秒跳转）

## 五、数据模型的几条经验

- 金额一律用「分」保存的整数，显示时统一两位小数。
- 状态用字符串枚举 + `CHECK` 约束，别用数字；状态迁移一律 `UPDATE ... WHERE status = 旧状态`，天然防重复提交和并发。
- 会造成删除困扰的东西（内容、商品）用软删除 + 快照，历史记录才不会烂掉。
- 搜索字段单独存一列归一化文本（去标点、转小写、全角转半角），否则「哈利·波特」搜不到。
- 会员名唯一索引加 `COLLATE NOCASE`，注册时再做 NFKC 归一化，防止大小写和全角冒充。

## 六、把产品逻辑写进 docs/需求拆解.md

骨架里已经有模板。至少写清楚：复刻对象与年代、核心闭环、角色、砍/换表、数据模型、演示数据规模、验收清单。这份文档和 README 是这个站唯一的权威说明。
