# 复刻一个 2003 年版的网站

把一个现代产品（小红书、淘宝、微博、Notion……）重做成 1999-2005 年的网页形态：表格排版、点阵宋体、跑马灯、访客计数器，但功能是真的——能注册、能发布、能交易、能管理，数据落库，可以部署上线。

参考实现在本仓库 `sites/xhs2003`（门户社区）和 `sites/taobao2003`（C2C 交易），遇到拿不准的写法就去这两个站里找同类代码。

## 什么时候用这个 skill

用户想「把某个产品做成复古版」。如果用户只是要一个普通的现代网站，不要用这个 skill。

## 工作流程

按顺序做，每一步做完再进入下一步。**第 1 步必须先问用户**，其余步骤尽量自己决策，不要反复打断。

### 1. 先问清三件事（必须）

1. **复刻哪个产品？** 要具体到「小红书」「大众点评」，不是「一个社区」。
2. **哪一年？** 1999-2005 之间选一年。年份决定形态：1999 是纯表格 + 动图，2003 是门户三栏 + 渐变标题条，2005 开始有圆角和 Web2.0 味。
3. **最想留下哪一件事？** 用户来这个站最重要的一个动作（发帖/买东西/听歌/记笔记）。这就是核心闭环，必须做通。

其余的（配色、站名、要不要后台）可以自己定，做完给用户看效果再调。

### 2. 研究年代形态

读 `references/era-guide.md`：当年的视觉元素、交互方式、每类产品的真实对应物，以及哪些现代功能必须砍掉或替换。

产出：在脑子里（或草稿里）确定这个站长什么样、有哪几个页面、导航条上放什么。

### 3. 写需求拆解

读 `references/product-design.md`，把产品拆成：核心闭环（3-6 步）、角色与场景、砍掉/替代清单、数据模型、页面清单。
先写成文档再动手，写完给用户看一眼确认方向，然后开工。

### 4. 生成骨架

```bash
node skills/retro-site/scripts/new-site.mjs \
  --slug weibo2005 --name "微博 2005" --port 3005 \
  --tagline "随时随地分享新鲜事" --theme "#d4213d" --width 800 --admin "站长"
cd sites/weibo2005 && npm install && npm test
```

生成的骨架已经能跑：会员注册登录、内容列表与详情、发布（带图上传）、留言、顶一下、个人空间、站长后台、演示数据、8 项集成测试 + 2 项浏览器测试、Dockerfile。**先确认 `npm test` 全绿再改代码。**

`--theme` 只需要给主色，深浅色会自动推导。`--width` 是页面宽度：1999-2001 用 760，2002-2004 用 778 或 800，2005 用 900。

### 5. 把示例业务换成真正的产品

骨架里的「内容 / 留言」是占位的示例。按需求拆解替换：

- `src/db/schema.sql`：把 `entries` / `comments` 换成你的表（宝贝、订单、歌曲、文档……）。开发期直接改 schema 重建库；上线后只能在 `src/db/index.js` 的迁移数组末尾追加。
- `src/services/*.js`：业务规则（校验、状态机、权限）放这里，路由只做参数解析和渲染。
- `src/routes/*.js`、`views/*.njk`：一个领域一个文件。
- `views/layout.njk`：导航条、页头、页脚按原型改。

写代码时守住 `references/quality.md` 里的硬性规则（CSRF、转义、参数化 SQL、越权校验、限速、CSP、点阵字号配对）。

### 6. 视觉还原

读 `references/visual.md`。要点：

- 改 `public/css/site.css` 顶部的 `--theme` 系列变量和页面宽度。
- **凡是写 `font-size` 的地方都要同时写对应的点阵字体族**：`font-size:14px;font-family:var(--f-song-14)`。不配对，点阵字会被缩放糊掉，这是最常见的翻车点。
- 有设计稿就用 Playwright 把原型和站点截同一状态的图，逐项比对宽度、颜色、边框、间距。

### 7. 造演示数据

读 `references/demo-data.md`。目标是「一打开就像运营了一两年」：几十个会员、上百条内容、按时间散布、有互动痕迹。改 `scripts/seed-data.js`，保持幂等（重复导入不会写第二遍）。

### 8. 测试与自检

```bash
npm test                                   # 集成测试：每个功能点的主路径 + 错误路径
npm run test:e2e                           # 浏览器端到端：走完核心闭环，控制台零报错
npm run crawl -- http://127.0.0.1:<端口>    # 爬站：404/500、模板残留
```

三样全绿才算完成。清单见 `references/quality.md`。

### 9. 交付与部署

- 更新站点 `README.md`：功能清单、路由表、数据模型、演示账号、已知限制。
- 在仓库根目录的 `docker-compose.yml`、`package.json`、`README.md` 里登记新站点。
- 部署读 `references/deploy.md`（本地 Docker / Nginx / Cloudflare Tunnel 三种）。
- 上线前：换强密码、`SEED_DEMO=false`、检查商标与免责声明。

## 硬性规则

1. **功能必须是真的**：每个能点的东西背后都有真实逻辑和数据，不做假按钮、假数据、假流程。
2. **形态必须是当年的**：表格排版、内联风格、跑马灯、闪烁 NEW、访客计数器；不用圆角卡片、大留白、现代前端框架。
3. **不写前端构建**：服务端渲染 + 原生 JS 渐进增强，关掉 JS 站点也能用。
4. **安全不打折**：CSRF、转义、参数化 SQL、越权校验、限速、CSP 一样不少。
5. **测试必须通过**：集成测试 + 至少一个浏览器端到端测试 + 爬站自检。
6. **法律红线**：站名和界面是致敬，代码全部原创；不使用真实商标图形；不接真实支付，站内资金是演示数字；README 里写清楚免责声明。
